# FlareTune Client 设计入口

## 当前有效方向

2026-11-12 用户明确：**主界面 UI 借鉴 Spotify，全屏播放器借鉴 Apple Music**。上一版仅有功能列表、悬浮条和简单播放器的视觉完成度被用户否定；它是功能基础，不是已获用户认可的首版 UI。

首版继续由开发自主完成，优先复用成熟组件与现有服务端能力，用户在首版完成后参与细节优化。Kotlin + Compose + Media3、Android 优先、独立原生页面继续有效。

## 本轮听歌能力补全（2026-11-12后续授权）

用户明确授权本协作先实现完整可用的基础UI，Gemini后续迭代；在本任务范围替代此前UI仅Gemini的协作限制。保留已有页面、封面氛围、图标、字体与响应式规则，不重建皮肤。当前原文/译文恢复已由用户确认；用户挂机后只做本机验证，不操作平板。

新增歌曲操作复用三点与Material3底部动作面板，提供带文字的收藏、下一首、队列、加入歌单和已有专辑/歌手入口。新建/编辑歌单使用可滚动名称/简介表单、明确取消/保存，保存中禁重复；失败保留草稿，成功后同步详情和资料库。删除歌单与清空历史有具体对象/后果确认。歌单排序区分完整成员与可播放投影，提供可访问的上下移动并支持拖动；编辑时有显式保存/取消，修订冲突不自动覆盖。批量歌曲选择显示数量与可操作动作。48dp目标、safeDrawing、200%字号、窄屏与宽屏真实约束继续适用。

本次不增加假成功按钮、管理/插件配置入口或新推荐算法。数据完整性与接口行为由[本轮任务](tasks/android-listening-capabilities-20261112.md)验收，视觉基础供后续优化。

## 本轮采用的界面规则

### Spotify 主界面

- 从默认歌曲列表升级为“主页 / 发现 / 搜索 / 个人歌单库”四入口（替代此前 3 Tab 及“将歌手 / 专辑放到主页”的过渡方案；底栏第四项命名仍对应用户的个人歌单库，避免误解为全库总览）。
  - **主页（Home）**聚焦个人高频听歌：自上而下依次为常驻顶部的 Spotify 式高利用率紧致顶栏（[ShellTopHeaderRow](../android/app/src/main/java/com/flaretune/client/ui/ListeningShell.kt) 统一样式：`44dp` 头像容器配 `34dp` 圆标 + 横向锚点胶囊 `全部` / `继续收听` / `随机推荐` / `来自你的曲库`，右上角不再放置刷新按钮，全局刷新统一置于头像下拉菜单 `account_refresh`）→ 快捷入口区（我喜欢的含一键播，展示最新收藏单曲封面而非自绘红心、播放历史、当前队列、收听统计）→ **继续收听**（基于近期反复收听4首 + 收藏3首 + 累计常听3首 + 最近搜索点播2首的混合快照，最多12首；24小时重复优先于7天重复，按来源/稳定ID去重且保留版本，各池顺延/跨池补位，耗尽显示实际数量，仅启动/手动刷新更新；`ContinueListeningGridTile` 内字号、行高、内边距与箭头尺寸随卡片 `size` 等比缩放）→ **随机推荐 / 随机听歌**（消费 `randomSongs`，支持换一批，点击换队列符合推荐流预期）→ **来自你的曲库**（按曲库各语言含未打标 `NULL / ""` 的歌曲数量比例展示每个语种最新入库单曲，提供显式 **播放全部** 按钮；单曲点击采用插播并立即播放，不替换当前队列）。点选顶栏胶囊不隐藏其余分区，而是平滑滚动定位至目标区块并随滚动位置同步胶囊高亮。
  - **发现（Discover）**聚焦全库漫游与分类浏览：自上而下依次为同一套常驻顶部的紧致顶栏（头像 + 紧致横向纯名称 **语言分类胶囊** 如“全部 / 华语 / 欧美 / 日语 / 纯音乐”，不展示数字计数，右上角无刷新按钮）→ **曲库歌手信息流**（`artists` 横向头像流与全部入口，不展示焦点音乐人卡片；全站外部歌手卡片及歌手详情头部统一隐藏“多少首歌曲 · 多少张专辑”统计文案）→ **专辑浏览流** → **曲库歌曲流**（随语言分类筛选）。
  - **搜索（Search）**与 **个人歌单库（原“资料库”）**同步采用同一套 `ShellTopHeaderRow` 紧致顶栏（左侧同位置 `AccountAvatar`，搜索页右侧接 `48dp` 胶囊搜索框，歌单库右侧接“个人歌单库 / + 创建歌单 / 排序与顺序调整”胶囊，均移除右上角刷新按钮；全站次级详情页/弹窗亦统一移除右上角刷新图标）。搜索结果支持显式 **播放全部** 与 **多选** 批量操作栏，单曲点播采用插播并立即播放而不覆盖当前队列。个人歌单库支持多种预设排序（默认/自定义顺序、最近更新、名称 A–Z、曲目数）及自定义拖拽排序；在窄屏/小窗（`maxWidth < 600dp`）采用垂直 **Spotify 式列表样式（`PlaylistListRow`）**：左侧 `58dp` 圆角封面、中间歌单名称与副标题/曲目数、右侧独立 `48dp` 更多按钮（不压挡封面），在 `>= 600dp` 保持多列 `PlaylistGridCard` 网格卡片。搜索预搜索态展示可单独移除的“最近搜索词胶囊”与“最近搜索卡片”（单曲快捷播放/歌手直达），采用与主页一致的**乐观视图快照锁**：点击“最近搜索”卡片快捷播歌/打开歌手不重排记录；新检索或搜索结果点播仅静默落盘，页面展示列表在进入应用/手动刷新后保持锁定，仅显式单项移除或清空立即同步。导航与播放条独立，不能占用相同触摸位置。
- 主页卡片使用实例真实专辑、当前播放队列和曲库歌曲；专辑打开完整详情并可播放。服务端已有专辑列表/详情接口直接复用，不把首批歌曲伪装成完整专辑，不制作假推荐和假计数。
- 封面为主视觉，文字只承担标题、类型、艺人层级；卡片宽度随窗口在约 148–212dp 范围内变化，横向架露出下一张。区块标题约 21sp（紧致 `16dp/8dp` 上下间距），避免顶部冗余留白；**主页/发现/搜索/歌手页歌曲区块（`UnifiedSongSectionList`）保留标准 `SongRow` 行高（至少 78dp、56dp 行内封面、标题单行约 15sp `titleMedium` / 副标题与时长 13sp `bodyMedium` + 竖向更多按钮），布局为 4 行一列的横向滚动信息流（继续收听最多 12 首 = 3 列，目录/发现/搜索/歌手页最多 16 首 = 4 列）：宽屏（`>= 700dp`）单列宽约为屏幕 2/5，双列并排并在右侧露出第三列约 1/5；窄屏单列占约 86% 宽并露出下一列**，避免大屏单列横向过度拉伸与纵长拉高页面。顶部 4 张快捷卡按屏宽等比响应放大：手机/窄窗（`< 600dp`）占约 `80%` 宽（`264–344dp × 160–200dp`，不再缩至 `248×142dp`）、中屏（`600–839dp`）约 `50%` 宽（`300–360dp × 174–208dp`）、宽屏（`>= 840dp`）约 `34%` 宽（`328–376dp × 190–214dp`），专辑封面尺寸保持不变。
- 深色采用 #121212 页面、#1F1F1F 浮层、#282828 快捷卡。主界面以绿色选中/播放锚点建立与参考一致的层级（本轮实施选择，替代旧暖橙局部方案）；浅色使用对应高对比度中性色和深绿色。正文不靠强调色分层。
- 筛选胶囊视觉约32dp（触控高度48dp），头像容器44dp（绿圆34dp），当前项通过填充与语义共同区分。主页/发现/搜索/个人歌单库四个主标签页顶部采用统一的 **`FrostedHeaderScaffold` Spotify 式纯渐变半透明浮动顶栏**：顶部安全边距取 `max(safeDrawing.top, 24dp)`（兼顾系统状态栏/挖孔/`captionBar` 与分屏/自由小窗顶部 `• • •` 拖拽条，避免 `AccountAvatar`、胶囊和搜索栏被遮挡）；顶栏悬浮于滚动内容之上，使用缓存的纵向渐变半透明遮罩随滚动位置柔和加深并平滑羽化底边（取代此前全屏离屏采集 + `API 31+ BlurEffect` 方案，避免列表滚动离屏重绘损耗），保持跨系统版本一致流畅。账号级操作（如刷新、退出登录）进入头像菜单，个人统计与高频回听/随机放主页，歌手/专辑/语言分类进发现页，主页不常驻管理工具栏并避免重复放置多个“刷新”按钮。
- 底部为真实的主页、发现、搜索、个人歌单库（4 Tab，四主入口各自保持滚动与局部状态并在点按已激活当前 Tab 时平滑回顶；兼顾宽屏/平板底部浮窗比例，窄屏控制短标签不换行）。**窄窗口（`< 840dp`，含手机、竖屏平板与窄浮窗）参考 YT Music 贴底停靠形态**：迷你播控改为全宽贴边实底条（移除左右 `8dp` 边距、外层圆角与半透卡底），直贴导航栏上方；全屏播放器展开/拖动收起时，底栏按展开进度 `p` 与面板下沿做严格 **1:1 线性同步位移**（无独立 alpha/缓动），封面飞入与面板同频 1:1 跟手过渡（移除下层主页缩沉以保障高帧率合成），收尾采用临界阻尼物理弹簧（`CompactPlayerSettleSpring`，继承手势初速度平滑收短），并在实色底栏内保留 `max(navigationBarsBottom, 14dp)` 底部安全净空；**宽窗口（`>= 840dp`）**：继续保留并排悬浮双浮岛（总宽约占屏幕 86%、`760–1020dp`，高 `78dp`，主导航与迷你播控约 `58% : 42%`，迷你播控禁用垂直上滑手势），展开全屏时浮岛原地柔和微暗让位（移除缩放），全屏播放器采用贴合系统视窗的**下方整体滑入**（`WidePlayerSlideSpring`）且左右分栏歌词在首帧即完整就位，替代此前宽屏右下浮岛变形与歌词延迟挂载方案。判断基于 BoxWithConstraints 等实际窗口尺寸，支持分屏/自由窗口，不按设备型号决定。

### Apple 全屏播放器

- 移除旧橙色圆底主播放键和页面式工具条。使用收起握柄/上下文、占主视觉的大封面、左对齐歌名艺人、轻细中性进度、宽松的上一首/主播放/下一首三键区与次级动作。
- 文字和播控主要为中性色；封面模糊/渐变提供氛围，强制遮罩保证正文至少4.5:1。没有封面或关闭氛围时仍有完整中性构图。
- 封面圆角约12–14dp，窄屏约宽度减64dp；宽屏以封面/控制双列适配，不把手机单列缩在屏幕中央。短窗口和200%字号允许滚动，动作不重叠。
- 保留拖动、键盘与可访问定位能力；最新进度条采用下方加粗无圆点 `StreamlinedTrackBar`（替代旧版“3–4dp 标准 Slider”规则），至少48dp触摸区；时长采用表格数字。
- 随机、循环、队列和重试均是真实动作。
