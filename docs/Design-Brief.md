# FlareTune Client 设计入口

## 当前有效方向

2026-11-12 用户明确：**主界面 UI 借鉴 Spotify，全屏播放器借鉴 Apple Music**。上一版仅有功能列表、悬浮条和简单播放器的视觉完成度被用户否定；它是功能基础，不是已获用户认可的首版 UI。

首版继续由开发自主完成，优先复用成熟组件与现有服务端能力，用户在首版完成后参与细节优化。Kotlin + Compose + Media3、Android 优先、独立原生页面继续有效。

## 已读依据和适用范围

- 用户提供的 Spotify 两张实机截图：横向平板和窄浮窗。采用头像与胶囊筛选、紧凑入口、大封面横向内容分区、底部导航和播放条；实际窗口约束决定并排或上下排列。
- [Spotify 研究](../research/docs/03-spotify.md)、[Apple Music 研究](../research/docs/04-applemusic.md)、[比较](../research/docs/05-comparison.md)和[原提案](../research/docs/06-flaretune-client-design.md)。研究中的推断与未知仍保持原标注。
- 助手新增的本地 APK 布局提取：Spotify `.research/out/spotify_layouts_decoded/` 的 funkis_home、funkis_filter_chips_header、carousel_row、glue_sectionheader_large、now_playing_bar 等；Apple 原始包的 fragment_player_main、music_player、player_progress_seek_bar、layout_player_buttons 及 w600dp 布局。仅取结构和参数依据，不依赖竞品业务运行库。
- 研究原件保持只读，尤其助手正在生成的提取文件。当前规则在本文件内落地，不要求后续会话重新反编译才能开发。

## 本轮听歌能力补全（2026-11-12后续授权）

用户明确授权本协作先实现完整可用的基础UI，Gemini后续迭代；在本任务范围替代此前UI仅Gemini的协作限制。保留已有页面、封面氛围、图标、字体与响应式规则，不重建皮肤。当前原文/译文恢复已由用户确认；用户挂机后只做本机验证，不操作平板。

新增歌曲操作复用三点与Material3底部动作面板，提供带文字的收藏、下一首、队列、加入歌单和已有专辑/歌手入口。新建/编辑歌单使用可滚动名称/简介表单、明确取消/保存，保存中禁重复；失败保留草稿，成功后同步详情和资料库。删除歌单与清空历史有具体对象/后果确认。歌单排序区分完整成员与可播放投影，提供可访问的上下移动并支持拖动；编辑时有显式保存/取消，修订冲突不自动覆盖。批量歌曲选择显示数量与可操作动作。48dp目标、safeDrawing、200%字号、窄屏与宽屏真实约束继续适用。

本次不增加假成功按钮、管理/插件配置入口或新推荐算法。数据完整性与接口行为由[本轮任务](tasks/android-listening-capabilities-20261112.md)验收，视觉基础供后续优化。

## 本轮采用的界面规则

### Spotify 主界面

- 从默认歌曲列表升级为“主页 / 搜索 / 个人歌单库”三入口（原“资料库”命名及将“歌手 / 专辑 / 收听统计”放入头像菜单的做法已由 2026-11-13 用户确认替代）。**主页**承担曲库发现与浏览，将“歌手”“专辑”“收听统计”等浏览入口放入主页可达位置；**个人歌单库**专注用户的“我喜欢的”与自建歌单及顺序管理。导航与播放条独立，不能占用相同触摸位置。
- 主页卡片使用实例真实专辑、当前播放队列和曲库歌曲；专辑打开完整详情并可播放。服务端已有专辑列表/详情接口直接复用，不把首批歌曲伪装成完整专辑，不制作假推荐和假计数。
- 封面为主视觉，文字只承担标题、类型、艺人层级；卡片宽度随窗口在约 148–212dp 范围内变化，横向架露出下一张。区块标题 22–24sp，间距 24–32dp；列表用 48–56dp 封面、至少72dp行。
- 深色采用 #121212 页面、#1F1F1F 浮层、#282828 快捷卡。主界面以绿色选中/播放锚点建立与参考一致的层级（本轮实施选择，替代旧暖橙局部方案）；浅色使用对应高对比度中性色和深绿色。正文不靠强调色分层。
- 筛选胶囊视觉约36dp，操作区至少48dp；头像32dp，当前项通过填充与语义共同区分。账号级操作（如刷新、退出登录）进入头像菜单，内容浏览入口放在主页，主页不常驻管理工具栏并避免重复放置多个“刷新”按钮。
- 底部为真实的主页、搜索、个人歌单库入口。窄窗口：播放条在导航上方；宽窗口约840dp起：导航与播放条并排，参考用户横向截图。判断基于 BoxWithConstraints 等实际窗口尺寸，支持分屏/自由窗口，不按设备型号决定。

### Apple 全屏播放器

- 移除旧橙色圆底主播放键和页面式工具条。使用收起握柄/上下文、占主视觉的大封面、左对齐歌名艺人、轻细中性进度、宽松的上一首/主播放/下一首三键区与次级动作。
- 文字和播控主要为中性色；封面模糊/渐变提供氛围，强制遮罩保证正文至少4.5:1。没有封面或关闭氛围时仍有完整中性构图。
- 封面圆角约12–14dp，窄屏约宽度减64dp；宽屏以封面/控制双列适配，不把手机单列缩在屏幕中央。短窗口和200%字号允许滚动，动作不重叠。
- 标准 Compose Slider 保留拖动、键盘、可访问定位能力；进度轨道约3–4dp，至少48dp触摸区；时长采用表格数字。
- 随机、循环、队列和重试均是真实动作。
- 2026-11-13 用户确认（全屏更多菜单与歌曲操作重构）：
  - **不再内置 App 音量滑块**：Android 端直接使用系统/物理音量控制，不在全屏播放器或 `SongActionsSheet` 内暴露 `MediaController.volume` 倍率调节（替代此前“复用 `Media3 Player` 做播放器音量”的条款）。底层遗留相关代码（`ClientActions.setVolume`、`PlaybackSnapshot.volume`、`AndroidPlaybackGateway.setVolume`、`ClientViewModel.setVolume`、`ClientIcons.VolumeLow`/`VolumeHigh` 及对应偏好持久化）保留待后续由其他协作者统一清理。
  - **全屏播放器保持封面模糊背景不变**：移除原白色弹窗里的“封面背景 / 纯色背景”切换项，点击播放器三个点直接复用全局 [`SongActionsSheet`](../android/app/src/main/java/com/flaretune/client/ui/LibraryDialogs.kt) 编辑当前歌曲。
  - **歌曲操作菜单（YT Music 结构，随应用深浅色）**：继续复用 [`FlareModalSheet`](../android/app/src/main/java/com/flaretune/client/ui/ListeningComponents.kt) 容器（浅色/深色随系统主题）；顶部展示 `歌名`、`歌手 · 时长` 与右侧 `×` 关闭按钮及细分隔线；紧接 3 列常用圆角快捷卡片（**下一首**、**加入播放列表**、**我喜欢**）；下方图标列表展示 **加入播放队列**、**查看歌手**、**查看专辑** 及歌单内 **从此歌单移除**。
  - **全局三个点改竖向**：[`ClientIcons.More`](../android/app/src/main/java/com/flaretune/client/ui/ClientIcons.kt) 统一切换为竖排三点，减少横向视觉占位。
- 歌词和收藏已有真实状态/动作时提供入口；投屏或音质等无数据能力不放置占位按钮。首版不做黑胶或持续装饰动画。
- 2026-11-13 用户确认：横屏歌词翻译按钮中心与左侧播控处于同一高度；关闭为灰色，启用为高亮白色，透明背景沿用播控，不使用独立蓝色底/边框。封面氛围与中性文字保持统一，静态封面层替代持续多层旋转模糊；歌词通过轻量透明度突出当前行，不以逐行动画模糊影响跟随。自动跟随不触发手动浏览暂停，只有真实拖动暂停，浏览结束后恢复。
- 歌词与翻译入口只消费网页共用接口的结果：有无词、译文可用性、翻译支持与无需翻译由服务端返回。客户端不按歌名、语种或字符自行决定翻译资格；显示偏好与明确请求生成分开，失败保留已有原文。用户本轮纠正撤销了尝试加入客户端的语种拦截，该方案不属于当前设计。

### 共用基础

- **系统媒体与品牌（2026-11-13）**：非空队列的上一首/下一首保持显示，首尾操作沿用原队列规则。用户明确软件图标尚未选定；撤回本轮临时套用的三条声波资源，仅制作成对的软件/通知SVG候选，选定前不安装品牌变更。通知候选必须是透明单色遮罩，小尺寸仍可辨识。

系统字体、系统中文回退、统一24dp矢量图标；不把竞品提取字体、Logo、账号/业务代码和原始APK打入应用。继续复用 Compose、Media3、OkHttp、Coil，无新 UI 框架。

连接与必要改密采用完整可滚动表单；密码不保存。加载、空、失败、分页失败和播放错误分别呈现。遵循安全区、Android返回、至少48dp触摸区、系统明暗与字号放大；当前状态不只用颜色表达。

### 前端体验审查与优化规则（2026-11-13）

- **导航、返回栈与命名边界**：全屏播放器展开歌词态、主页“全部歌曲/全部专辑”、歌手详情子视图、搜索分类子视图均需正确拦截系统返回键退回上一局部视图；浏览歌词期间切歌保留歌词视图。底栏原“资料库”统一改为“个人歌单库”（短标签可用“歌单库”，视窄屏宽度保持不换行）；“歌手”“专辑”“收听统计”移入主页可达入口；全局统一“歌单”中文术语（不再混用“加入播放列表”与“加入歌单”）。
- **歌曲来源与导航（2026-11-13实测修复）**：查看歌手/专辑保持宿主返回的真实来源ID；YT缺引用不能回退本地同名实体，已知专辑直接打开详情。菜单导航收起全屏播放器，即使目标原本已经打开。专辑详情“正在播放”核对具体歌曲和专辑关联，点播当前列表不能被旧队列的其他版本上下文覆盖。
- **播放语义与防误触**：点击主页“继续收听”或播放历史曲目时，载入当前历史列表并从点击位置立即连续播放；播放历史单曲移除提供防误触确认/撤销或收进歌曲更多菜单；歌单详情“编辑歌曲顺序”按钮直接打开排序面板；全屏播放页 `keepScreenOn` 仅在真实 `playing` 时启用。
- **细节反馈与过渡动画**：收藏、下一首播放、加入队列与循环模式切换提供轻提示反馈（不遮挡底栏与迷你播放条）；迷你播放条左右切歌、拖拽排序、进度拖动与收藏补齐适度触觉反馈；缓冲期封面维持播放态比例不抽搐；翻译生成 `pending` 态展示加载指示器；严格落实不施加逐行歌词 `Modifier.blur`；一级/二级页面切换、筛选胶囊、播放页系统返回与动态背景渐变色补齐轻量过渡动画；歌单排序改用 `LazyColumn` 且未修改时禁用保存。
- **代码与工程卫生边界**：消除重复的 `QueuePanel` 挂载与多处冗余刷新按钮；后续清理 `CatalogScreen` 不可达分支、`PlaylistOrderDialog`、已废弃音控残余及未使用字符串资源（先待当前在途脏工作树拆批收敛）。
- **后续交付参考**：具体分优先级整改清单见 [前端体验优化任务](tasks/android-frontend-polish-20261113.md)。

## 验证与替代关系

本轮以包含足够歌曲、专辑和不同封面的真实组件 fixture 检查构图，不再用“两条无封面数据”作为首页完成度的主要证据。检查390dp窄屏、约840/1280dp宽屏、窄浮窗和200%字号；截图需标明模拟/真机来源并目视对照用户参考，交互单独运行。

原“只显示品牌”骨架、简单列表作为首页、暖橙色圆形全屏主键等已由本轮规则替代。上一版构建/认证审查证据继续适用于未改动的范围；旧视觉截图不代表本轮 UI 验收。范围和状态见 [当前任务](tasks/android-listening-ui-20261112.md)。

调试预览：用户询问快速查看修改后，新增仅debug的独立预览进程，使用本地样例展示相同Compose组件，并提供覆盖安装后重启的监听脚本。它不是正式音乐入口或Live Edit；实际设备已目视主页与播放器，持续watcher未常驻。
