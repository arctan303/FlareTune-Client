# FlareTune Client 设计入口

## 当前有效方向

2026-11-12 用户明确：**主界面 UI 借鉴 Spotify，全屏播放器借鉴 Apple Music**。上一版仅有功能列表、悬浮条和简单播放器的视觉完成度被用户否定；它是功能基础，不是已获用户认可的首版 UI。

首版继续由开发自主完成，优先复用成熟组件与现有服务端能力，用户在首版完成后参与细节优化。Kotlin + Compose + Media3、Android 优先、独立原生页面继续有效。

## 已读依据和适用范围

- 用户提供的 Spotify 两张实机截图：横向平板和窄浮窗。采用头像与胶囊筛选、紧凑入口、大封面横向内容分区、底部导航和播放条；实际窗口约束决定并排或上下排列。
- [Spotify 研究](../research/docs/03-spotify.md)、[Apple Music 研究](../research/docs/04-applemusic.md)、[比较](../research/docs/05-comparison.md)和[原提案](../research/docs/06-flaretune-client-design.md)。研究中的推断与未知仍保持原标注。

## 本轮听歌能力补全（2026-11-12后续授权）

用户明确授权本协作先实现完整可用的基础UI，Gemini后续迭代；在本任务范围替代此前UI仅Gemini的协作限制。保留已有页面、封面氛围、图标、字体与响应式规则，不重建皮肤。当前原文/译文恢复已由用户确认；用户挂机后只做本机验证，不操作平板。

新增歌曲操作复用三点与Material3底部动作面板，提供带文字的收藏、下一首、队列、加入歌单和已有专辑/歌手入口。新建/编辑歌单使用可滚动名称/简介表单、明确取消/保存，保存中禁重复；失败保留草稿，成功后同步详情和资料库。删除歌单与清空历史有具体对象/后果确认。歌单排序区分完整成员与可播放投影，提供可访问的上下移动并支持拖动；编辑时有显式保存/取消，修订冲突不自动覆盖。批量歌曲选择显示数量与可操作动作。48dp目标、safeDrawing、200%字号、窄屏与宽屏真实约束继续适用。

本次不增加假成功按钮、管理/插件配置入口或新推荐算法。数据完整性与接口行为由[本轮任务](tasks/android-listening-capabilities-20261112.md)验收，视觉基础供后续优化。

## 本轮采用的界面规则

### Spotify 主界面

- 从默认歌曲列表升级为“主页 / 发现 / 搜索 / 个人歌单库”四入口（替代此前 3 Tab 及“将歌手 / 专辑放到主页”的过渡方案；底栏第四项命名仍对应用户的个人歌单库，避免误解为全库总览）。
  - **主页（Home）**聚焦个人高频听歌：自上而下依次为常驻顶部的 Spotify 式高利用率紧致顶栏（[ShellTopHeaderRow](../android/app/src/main/java/com/flaretune/client/ui/ListeningShell.kt) 统一样式：`44dp` 头像容器配 `34dp` 圆标 + 横向锚点胶囊 `全部` / `继续收听` / `随机推荐` / `来自你的曲库`，右上角不再放置刷新按钮，全局刷新统一置于头像下拉菜单 `account_refresh`）→ 快捷入口区（我喜欢的含一键播，展示最新收藏单曲封面而非自绘红心、播放历史、当前队列、收听统计）→ **继续收听**（基于近期反复收听4首 + 收藏3首 + 累计常听3首 + 最近搜索点播2首的混合快照，最多12首；24小时重复优先于7天重复，按来源/稳定ID去重且保留版本，各池顺延/跨池补位，耗尽显示实际数量，仅启动/手动刷新更新）→ **随机推荐 / 随机听歌**（消费 `randomSongs`，支持换一批）→ 常听摘要 / 曲库速览兜底；点选顶栏胶囊不隐藏其余分区，而是平滑滚动定位至目标区块并随滚动位置同步胶囊高亮。
  - **发现（Discover）**聚焦全库漫游与分类浏览：自上而下依次为同一套常驻顶部的紧致顶栏（头像 + 紧致横向纯名称 **语言分类胶囊** 如“全部 / 华语 / 欧美 / 日语 / 纯音乐”，不展示数字计数，右上角无刷新按钮）→ **曲库歌手信息流**（`artists` 横向头像流与全部入口，不展示焦点音乐人卡片）→ **专辑浏览流** → **曲库歌曲流**（随语言分类筛选）。
  - **搜索（Search）**与 **个人歌单库（原“资料库”）**同步采用同一套 `ShellTopHeaderRow` 紧致顶栏（左侧同位置 `AccountAvatar`，搜索页右侧接 `48dp` 胶囊搜索框，歌单库右侧接“个人歌单库 / + 创建歌单 / 调整歌单库顺序”胶囊，均移除右上角刷新按钮；全站次级详情页/弹窗亦统一移除右上角刷新图标）。个人歌单库在窄屏/小窗（`maxWidth < 600dp`）采用垂直 **Spotify 式列表样式（`PlaylistListRow`）**：左侧 `58dp` 圆角封面、中间歌单名称与副标题/曲目数、右侧独立 `48dp` 更多按钮（不压挡封面），在 `>= 600dp` 保持多列 `PlaylistGridCard` 网格卡片。搜索预搜索态展示可单独移除的“最近搜索词胶囊”与“最近搜索卡片”（单曲快捷播放/歌手直达），采用与主页一致的**乐观视图快照锁**：点击“最近搜索”卡片快捷播歌/打开歌手不重排记录；新检索或搜索结果点播仅静默落盘，页面展示列表在进入应用/手动刷新后保持锁定，仅显式单项移除或清空立即同步。导航与播放条独立，不能占用相同触摸位置。
- 主页卡片使用实例真实专辑、当前播放队列和曲库歌曲；专辑打开完整详情并可播放。服务端已有专辑列表/详情接口直接复用，不把首批歌曲伪装成完整专辑，不制作假推荐和假计数。
- 封面为主视觉，文字只承担标题、类型、艺人层级；卡片宽度随窗口在约 148–212dp 范围内变化，横向架露出下一张。区块标题约 21sp（紧致 `16dp/8dp` 上下间距），避免顶部冗余留白；**主页/发现/搜索/歌手页歌曲区块（`UnifiedSongSectionList`）保留标准 `SongRow` 行高（至少 78dp、56dp 行内封面、标题单行约 15sp `titleMedium` / 副标题与时长 13sp `bodyMedium` + 竖向更多按钮），布局为 4 行一列的横向滚动信息流（继续收听最多 12 首 = 3 列，目录/发现/搜索/歌手页最多 16 首 = 4 列）：宽屏（`>= 700dp`）单列宽约为屏幕 2/5，双列并排并在右侧露出第三列约 1/5；窄屏单列占约 86% 宽并露出下一列**，避免大屏单列横向过度拉伸与纵长拉高页面。顶部 4 张快捷卡按屏宽等比响应放大：手机/窄窗（`< 600dp`）占约 `80%` 宽（`264–344dp × 160–200dp`，不再缩至 `248×142dp`）、中屏（`600–839dp`）约 `50%` 宽（`300–360dp × 174–208dp`）、宽屏（`>= 840dp`）约 `34%` 宽（`328–376dp × 190–214dp`），专辑封面尺寸保持不变。
- 深色采用 #121212 页面、#1F1F1F 浮层、#282828 快捷卡。主界面以绿色选中/播放锚点建立与参考一致的层级（本轮实施选择，替代旧暖橙局部方案）；浅色使用对应高对比度中性色和深绿色。正文不靠强调色分层。
- 筛选胶囊视觉约32dp（触控高度48dp），头像容器44dp（绿圆34dp），当前项通过填充与语义共同区分。主页/发现/搜索/个人歌单库四个主标签页顶部采用统一的 **`FrostedHeaderScaffold` Spotify 式纯渐变半透明浮动顶栏**：顶部安全边距取 `max(safeDrawing.top, 24dp)`（兼顾系统状态栏/挖孔/`captionBar` 与分屏/自由小窗顶部 `• • •` 拖拽条，避免 `AccountAvatar`、胶囊和搜索栏被遮挡）；顶栏悬浮于滚动内容之上，使用缓存的纵向渐变半透明遮罩随滚动位置柔和加深并平滑羽化底边（取代此前全屏离屏采集 + `API 31+ BlurEffect` 方案，避免列表滚动离屏重绘损耗），保持跨系统版本一致流畅。账号级操作（如刷新、退出登录）进入头像菜单，个人统计与高频回听/随机放主页，歌手/专辑/语言分类进发现页，主页不常驻管理工具栏并避免重复放置多个“刷新”按钮。
- 底部为真实的主页、发现、搜索、个人歌单库（4 Tab，四主入口各自保持滚动与局部状态并在点按已激活当前 Tab 时平滑回顶；兼顾宽屏/平板底部浮窗比例，窄屏控制短标签不换行）。**窄窗口（`< 840dp`，含手机与窄浮窗）参考 Spotify 贴底停靠形态**：取消悬浮与透明留空，底栏全宽贴底不透明，并适度加大触控与视觉占比（导航 `56dp`、`22dp` 图标配 `12sp` 标签；直贴导航栏上方的实色迷你播控卡 `62dp`、配 `44dp` 封面且支持上滑展开全屏播放器；仅 `8dp` 侧边留空与 `4dp/2dp` 极小上下边距，并在实色背景内保留 `max(navigationBarsBottom, 14dp)` 底部安全净空防止自由小窗手势指示条与导航文字重叠；内容底留白同步增至 `136dp`/`66dp` 并计入真实系统底栏与安全净空）；**宽窗口（`>= 840dp`）**：导航与播放条并排悬浮（总宽约占屏幕 86%、`760–1020dp`，高 `78dp`），且参考 Spotify 平板比例令主导航控件明显长于迷你播控条（约 `58% : 42%`）。判断基于 BoxWithConstraints 等实际窗口尺寸，支持分屏/自由窗口，不按设备型号决定。

### Apple 全屏播放器

- 移除旧橙色圆底主播放键和页面式工具条。使用收起握柄/上下文、占主视觉的大封面、左对齐歌名艺人、轻细中性进度、宽松的上一首/主播放/下一首三键区与次级动作。
- 文字和播控主要为中性色；封面模糊/渐变提供氛围，强制遮罩保证正文至少4.5:1。没有封面或关闭氛围时仍有完整中性构图。
- 封面圆角约12–14dp，窄屏约宽度减64dp；宽屏以封面/控制双列适配，不把手机单列缩在屏幕中央。短窗口和200%字号允许滚动，动作不重叠。
- 标准 Compose Slider 保留拖动、键盘、可访问定位能力；进度轨道约3–4dp，至少48dp触摸区；时长采用表格数字。
- 随机、循环、队列和重试均是真实动作。
- 2026-11-13 用户确认（全屏更多菜单与歌曲操作重构）：
  - **不再内置 App 音量滑块**：Android 端直接使用系统/物理音量控制，不在全屏播放器或 `SongActionsSheet` 内暴露 `MediaController.volume` 倍率调节（替代此前“复用 `Media3 Player` 做播放器音量”的条款）。底层遗留相关代码（`ClientActions.setVolume`、`PlaybackSnapshot.volume`、`AndroidPlaybackGateway.setVolume`、`ClientViewModel.setVolume`、`ClientIcons.VolumeLow`/`VolumeHigh` 及对应偏好持久化）保留待后续由其他协作者统一清理。
  - **全屏播放器保持封面模糊背景不变**：移除原白色弹窗里的“封面背景 / 纯色背景”切换项，点击播放器三个点直接复用全局 [`SongActionsSheet`](../android/app/src/main/java/com/flaretune/client/ui/LibraryDialogs.kt) 编辑当前歌曲。
  - **歌曲操作菜单（YT Music 结构，随应用深浅色）**：继续复用 [`FlareModalSheet`](../android/app/src/main/java/com/flaretune/client/ui/ListeningComponents.kt) 容器（浅色/深色随系统主题）；顶部展示 `歌名`、`歌手 · 时长` 与右侧 `×` 关闭按钮及细分隔线；紧接 3 列常用圆角快捷卡片（**下一首**、**加入歌单**、**我喜欢**）；下方图标列表展示 **加入播放队列**、**查看歌手**、**查看专辑** 及歌单内 **从此歌单移除**。
  - **全局三个点改竖向**：[`ClientIcons.More`](../android/app/src/main/java/com/flaretune/client/ui/ClientIcons.kt) 统一切换为竖排三点，减少横向视觉占位。
- 歌词和收藏已有真实状态/动作时提供入口；投屏或音质等无数据能力不放置占位按钮。首版不做黑胶或持续装饰动画。
- 2026-11-13 用户确认：横屏歌词翻译按钮中心与左侧播控处于同一高度；关闭为灰色，启用为高亮白色，透明背景沿用播控，不使用独立蓝色底/边框。封面氛围与中性文字保持统一，静态封面层替代持续多层旋转模糊；歌词通过轻量透明度突出当前行，不以逐行动画模糊影响跟随。自动跟随不触发手动浏览暂停，只有真实拖动暂停，浏览结束后恢复。
- 2026-11-13 用户确认（手机与窄浮窗全屏播放器）：移除底部标题旁独立歌词开关按钮（`⋮` 左侧不再占位），改为点击封面或预览歌词切入完整歌词、点击顶部歌名/小封面信息行切回封面，并通过 `SharedTransitionLayout` 为大小专辑封面提供连贯共享元素过渡；封面页中部歌词预览按真实剩余高度在「不显示 / 单行 / 双行（含译文或下一句）」间自适应，空间不足一整行时不显示以避免半行裁切；在 `syncMode == "word"` 逐字歌词模式下，封面下方预览条与底部迷你播放器 `ShellMiniPlayer`（全屏展开时暂停底栏计时，兼容浅/深色文字对比度）同步支持逐字卡拉OK渐进染色，其中封面下方预览条在单行超宽时平滑横向居中追踪当前演唱词进度，纯逐行歌词（`syncMode == "line"`）维持整行静态高亮；完整歌词页（窄屏单列）将「文A」译文显示开关并入顶部信息行与 `⋮` 并排并由歌词视口吃满全部剩余高度；底部进度条与主控按键区固定置于页面切换容器之外，封面页与完整歌词页保持完全一致的位置、高度、按钮尺寸与底边距，切换过程零位移。
- 歌词与翻译入口只消费网页共用接口的结果：有无词、译文可用性、翻译支持与无需翻译由服务端返回。客户端不按歌名、语种或字符自行决定翻译资格；显示偏好与明确请求生成分开，失败保留已有原文。2026-11-13 用户进一步确认：接口已有译文可直接提供显示开关，保留旧tlyric兼容，不额外要求支持新生成；not_needed即使夹带旧译文也不显示翻译按钮，纯音乐无翻译入口，unsupported/unavailable不提供生成动作。撤销把“非ready旧译文显示”一概视为漏洞并计划移除的审计建议。用户此前纠正撤销了客户端语种拦截，该方案仍不属于当前设计。

### 共用基础

- **系统媒体与品牌（2026-11-13）**：非空队列的上一首/下一首保持显示，首尾操作沿用原队列规则。用户明确软件图标尚未选定；撤回本轮临时套用的三条声波资源，仅制作成对的软件/通知SVG候选，选定前不安装品牌变更。通知候选必须是透明单色遮罩，小尺寸仍可辨识。

系统字体、系统中文回退、统一24dp矢量图标；不把竞品提取字体、Logo、账号/业务代码和原始APK打入应用。继续复用 Compose、Media3、OkHttp、Coil，无新 UI 框架。

连接与必要改密采用完整可滚动表单；密码不保存。加载、空、失败、分页失败和播放错误分别呈现。遵循安全区、Android返回、至少48dp触摸区、系统明暗与字号放大；当前状态不只用颜色表达。

### 前端体验审查与优化规则（2026-11-13）

- **导航、返回栈与命名边界**：全屏播放器展开歌词态、主页“全部歌曲/全部专辑”、歌手详情子视图、搜索分类子视图均需正确拦截系统返回键退回上一局部视图；浏览歌词期间切歌保留歌词视图。底栏四入口为“主页 · 发现 · 搜索 · 个人歌单库”（窄屏短标签可作“歌单库”或依词义统一）；高频“继续收听 / 随机听歌 / 收听统计”放主页，“语言分类 / 歌手流 / 专辑流 / 曲库流”归“发现”；全局统一“歌单”中文术语（不再混用“加入播放列表”与“加入歌单”）。
- **歌曲来源与导航（2026-11-13实测修复）**：查看歌手/专辑保持宿主返回的真实来源ID；YT缺引用不能回退本地同名实体，已知专辑直接打开详情。菜单导航收起全屏播放器，即使目标原本已经打开。专辑详情“正在播放”核对具体歌曲和专辑关联，点播当前列表不能被旧队列的其他版本上下文覆盖。
