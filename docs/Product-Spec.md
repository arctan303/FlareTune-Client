# FlareTune Android 首个可用版本

## 目标、依据与分工

2026-11-12 用户确认 Kotlin + Jetpack Compose + Media3、Android优先、独立原生页面与纯音乐消费体验。本轮用户进一步授权补齐网页普通账号的全部听歌能力：本协作可实施数据/API/状态/播放及基础UI，Gemini后续继续迭代视觉；这在本轮范围替代此前UI仅由Gemini修改的限制。用户离开挂机、不能反馈，后续仅在本机测试，不操作或重新安装挂机平板，不调用云端写入做验收。不扩展到iOS或新跨平台工程。

当前范围：连接实例、认证与会话、曲库/搜索/分类、本人收藏与歌单完整读写/顺序/封面/资料库组织、歌曲/专辑/歌手浏览及播放、统一歌词及译文状态、实际播放历史与清理、队列编辑和设备持久恢复、服务端合格收听统计、个人播放偏好与系统播控。具体对齐清单见[听歌能力补全任务](tasks/android-listening-capabilities-20261112.md)。UI接线以[Android数据合同](Android-Data-Contract.md)为准，视觉规则归[设计入口](Design-Brief.md)。

## 核心流程与验收

- **REQ-01 / AC-01 连接登录**：根HTTPS实例地址、用户名和密码；先检查ready，再按Cookie/Origin/CSRF协议登录。维护、网络失败可恢复；必须改密账号完成后重新登录。不提供初始化或管理员入口。
- **REQ-02 / AC-02 会话**：密码不持久化或写日志。Cookie以Android Keystore支撑的AES-GCM加密保存；支持同实例/跨实例多账号与旧单会话自动迁移，accountKey为规范origin+accountId。添加可取消并重新验活原账号；重启/切号向实例核验，不凭本机存档直接进入私人数据。切换已保存账号及取消新增账号直接触发冷启动开屏动画（`RESTORING` + `splashNonce`）加载；若会话恢复失败或需要重新认证，则回退至 `CONNECT` 并预填目标账号，支持免重输密码（未标 `needsReauth` 时）点击提交重试或点选已保存账号切回。非凭据实例地址可保留。
- **REQ-03 / AC-03 隔离**：会话只发同scheme/host/port，API不跟重定向；外部HTTPS媒体/图片不携带实例Cookie。退出、切换、401或精确账号不匹配停止旧播放、清活跃图片内存与私人数据内存、递增身份代次并拒绝迟到结果。历史/队列按origin+accountId隔离保留，重新绑定和验证媒体后暂停恢复；图片磁盘缓存同样按身份分区。本轮多账号规则替代原“切号/退出删除全部旧历史队列”。401仅清目标Cookie并标记needsReauth，保留其他账号；logout删除当前凭据回CONNECT；移除活跃账号按最近顺序尝试其余有效账号，皆无效回CONNECT。
- **REQ-04 / AC-04 曲库**：合法分类集合分页、搜索、本人收藏、专辑列表和完整详情；加载/空/失败/分页失败分别呈现，刷新保留内容。limit≤50、offset≤2000，到上限提示搜索，不假称全库已读。
- **REQ-05 / AC-05 播放**：按上下文区分播放语义——具备明确队列设计意图的功能（继续收听、随机推荐、歌单详情、专辑详情、我的收藏、歌手详情）点击歌曲以当前列表生成队列；单点发现与检索列表（搜索结果、首页“来自你的曲库”、播放历史歌曲）点击单曲默认插播至当前队列下一首并立即切播，保留原有队列并同步提供显式“播放全部”按钮用于主动替换队列。Media3 Player为唯一播放事实；play/pause/seek/next/previous/shuffle/repeat/gain与页面共享。上一首一次直接上一曲，无上一曲才归零。
- **REQ-06 / AC-06 系统音频**：MediaSessionService承载播放器，MediaController驱动页面；后台服务、通知栏/锁屏元数据、音频焦点与耳机拔出处理保留。真实蓝牙/锁屏/中断/厂商后台限制另做设备验证。
- **REQ-07 / AC-07 页面职责**：原生连接页、主页（快捷入口：我喜欢的以 `latestFavoriteCoverUrl` 展示最新收藏封面 / 继续收听 12 首乐观混排快照 / 随机推荐 / 来自你的曲库：按曲库真实语种比例含未打标歌曲展示各语种最新歌曲并配“播放全部”入口）/发现（纯名称语言分类筛选/曲库歌手流，所有歌手卡片与歌手详情页均不展示歌曲与专辑数量计数；专辑与歌曲浏览流）/搜索（最近搜索词与快捷卡片采取乐观快照锁，进入/手动刷新后保持锁定；点击最近搜索卡片快捷播歌插播下一首或打开歌手且不重排历史，仅显式移除/清空立即更新展示；离开搜索页、提交搜索、打开弹层/播放器或应用退后台时主动失焦并收起输入法，非活跃标签禁用焦点恢复）/个人歌单库（4 Tab，窄屏 `< 840dp` 为贴底实色紧缩布局，宽屏 `>= 840dp` 导航控件长于迷你播控条且并排悬浮、迷你播控条禁用垂直上滑手势仅留点击与左右切歌；支持歌单列表视图排序与拖动调序，二级页包括设置页保持内容可滚动至悬浮底栏下方）、独立全屏收听统计页、独立多标签播放历史页（歌曲 / 歌手 / 专辑·歌单 / 历史队列）、收藏/歌单/专辑（歌单详情支持视图排序与批量多选操作，搜索结果等歌曲列表支持批量多选）、迷你/全屏播放器（Mini 播放器支持左右滑切卡片式预览，含随机模式真实上下首与播超3秒场景；打开播放队列优先将当前播放曲目居中定位，拖动改序无整表闪烁；排除 `ime` 内边距以防外部键盘干扰；点击队列曲目切换播放不关闭队列，弹窗关闭按钮先完成收起动画再关闭）；主页/发现/搜索/歌手页歌曲区块统一复用保持 `SongRow` 行高（≥78dp）的 4 行多列横向信息流（宽屏单列约 2/5 宽、第三列露约 1/5；窄屏约 86% 宽）；动作使用同一ClientActions/快照，遵守safeDrawing、48dp触摸与字号放大。不以默认空动作可编译作为已接线证据。
- **REQ-08 / AC-08 交付**：APK、Lint、HTTP/隔离/状态与系统播放回归、签名检查及风险相称审查；模拟渲染和本地测试不替代真实听感、耗电、保活或全设备兼容。
- **REQ-09 / AC-09 歌词**：统一宿主GET与来源链；仅严格language=instrumental零网络纯音乐占位。词行/逐词时间以秒提供，激活索引随Player毫秒位置计算；明确无词、加载和失败分别展示，不能将未知结构/网络失败归无词。pending有界轮询、旧ref一次恢复、切歌/身份清旧结果。
- **REQ-10 / AC-10 个人歌单/收藏**：现代本人列表与完整详情，真实favorite ID；首页收藏封面按addedAt而非队列第一首；点击playFavorites重新取完整详情，不截断为首批。被动刷新不得覆盖明确播放意图。
- **REQ-11 / AC-11 历史与队列保护**：设备按origin+accountId分键持久化实际current+isPlaying记录，后台服务同样记录；最多200首、最近倒序/去重。暂停/恢复/拖动或队列成员不制造历史；新版独立二级播放历史页分为“歌曲 / 歌手 / 专辑·歌单 / 历史队列”四栏：记录最近访问歌手与最近播放专辑/歌单；当用户执行整列替换播放队列且原队列有效曲目 ≥ 2 首或经调整时，自动保存一份有界本地队列快照供随时一键恢复（只存安全展示元数据，点击仍需在当前身份下重新解析媒体）。播放历史页内点击单曲默认插播下一首并切播，“播放全部”按钮用于以完整历史列表替换队列（替代此前“点击历史单曲直接以完整历史替换队列”的旧规则）。主页“继续收听”与“播放历史”区隔：由真实近期重复收听、本人收藏、累计常听和最近搜索点播歌曲混排，12首目标配额为4/3/3/2；最近7天至少2次才属于重复收听，24小时重复听优先，累计次数作加权抽样。各来源顺延候选补足去重名额，来源耗尽跨池补位，全部耗尽展示实际数量；按来源与稳定ID去重，保留同名不同版本。启动/手动刷新生成并锁定，播歌/切歌期间不重排。搜索用当前实例/账号设备记录重新解析媒体，不能从锁定的旧搜索展示列表取数据；窗口响应须回显days/from/to，旧服务端忽略days不伪装近期统计，仅用其他可用来源。点击继续收听建立该混合列表队列。
- **REQ-12 / AC-12 持久队列**：最多500项/512KiB，保顺序和重复项，保存currentIndex/position/shuffle/repeat；Service事件/每2秒/正常销毁提交，启动空Player不冲掉磁盘。冷启验证账号和媒体后暂停恢复；缺失项跳过并提示，用户新播放/编辑优先。覆盖安装保留已提交的新版本数据，不从历史捏造旧版未保存队列。
- **REQ-13 / AC-13 分类**：songLanguage和albumLanguage独立；切换取消旧请求并重置对应分页，all转换为合法集合或省略参数，不向宿主传all字面值；未知歌曲language保留null。
- **REQ-14 / AC-14 译文显示**：translationEnabled设备持久化，默认false；toggle/set仅改显示，不POST、不改源/AI配置。requestLyricTranslation是当前有效歌词独立生成动作。保存失败保持原选择并报告安全错误。

- **REQ-15 / AC-15 本人歌单写入**：使用Web相同现代接口、CSRF/Expected-Account、expectedRevision及幂等规则，完成创建/改名/简介/删除、增删歌曲、完整顺序和资料库排序。收藏按真实favorite ID处理，收藏元信息保护保持。不可播放成员仍保留完整membership，排序不可静默删除；冲突刷新后由用户明确重试，不盲目覆盖。
- **REQ-16 / AC-16 歌曲操作、多选排序与历史整理**：歌曲行、当前播放及详情提供一致收藏/取消收藏（星标图标 + “加入收藏 / 已收藏”文案，点亮收藏后保持菜单不异常关闭）、加入歌单、播放下一首/加入队列及歌曲弹窗内**复制歌曲信息**（一键复制“歌名 - 歌手”，无歌手时仅复制歌名并给反馈）入口；歌单三点菜单提供封面头部、播放/随机/加入队列快捷动作与编辑/排序/多选/封面/删除列表；个人歌单库与歌单详情支持视图排序与一键重排，歌单详情/搜索结果/全部歌曲/专辑页支持批量多选操作栏；队列编辑保持实际Media3事实。历史单删/清空只改本地记录，不中断当前播放，不把整队列写进历史。
- **REQ-17 / AC-17 普通听歌对齐**：按实际Web能力补齐歌手/专辑/歌曲检索与详情、完整详情播放、个人歌单库组织、收听统计及播放偏好。无接口的推荐不伪造；虚拟来源只沿用已有统一宿主支持，不新增插件私有功能。
- **REQ-18 / AC-18 基础UI与本机验收**：沿用当前Spotify主界面/Apple播放器、Material3/token/图标。新增操作有忙态、真实成功、可重试错误、冲突反馈和删除确认；取消保留真实数据。窄屏/平板/大字号本地渲染及动作测试，HTTP/状态/播放回归、APK/Lint与R2独立复核；不声称本地测试等同本轮真机验收。
- **REQ-19 / AC-19 经典播放器跟随与风格**：横屏翻译按钮与左侧播控同高，透明底、关闭灰/开启白；自动滚动不作为手动浏览，连续切行及seek迅速跟随，真实拖动结束后恢复，译文改变行高后焦点正确。沿用封面氛围与轻量清晰文字，避免持续多层模糊重绘。
- **REQ-20 / AC-20 消费端边界**：Android与Web共用歌词接口。原文、已有译文、翻译支持及是否需要翻译由服务端判定并返回；客户端只按响应状态展示、轮询和在明确动作下请求翻译，不按曲名/语种/字符自行裁切。译文失败不能遮掉已取得原文（UI 通过翻译图标角标 `!` 与右侧重试按钮提示，不展示冗长正文说明）；不自行更改实例自动补全策略。2026-11-13 用户澄清：接口已经返回的译文（含行内tlyric兼容结果）保留显示，不因新生成不支持或unavailable而删除；not_needed明确禁止翻译按钮，即使响应仍带旧译文或supported=true。生成按钮与请求入口使用同一资格：supported=true且IDLE/FAILED可明确提交，PENDING仅显示进度、不可重复提交；纯音乐没有翻译入口。

- **REQ-21 / AC-21 前后台与页面恢复**：启动入口/媒体通知复用现有任务，退后台不主动导航首页；系统重建恢复同实例/账号的目的地、检索/筛选和详情ID并重新读取，不存媒体URL/凭据；退出/切号拒绝旧路由，全屏面板不被RESTORING误清。显式结束任务/清data不承诺页面恢复。
- **REQ-22 / AC-22 系统媒体动作**：同一Media3会话保留三播控，追加播放顺序和收藏，模式及收藏状态真实双向同步；后台无Activity仍可用。旧曲目命令/旧身份拒绝，现代本人歌单接口/revision、失败反馈与不乐观成功保持；最终槽位布局由Android/OEM决定。
- **REQ-23 / AC-23 后台休眠**：PlaybackService在后台/锁屏执行OFF、TIMED、END_OF_TRACK；定时到期短淡出后pause并立即恢复原音量，曲终原生拦截下一曲，完成归OFF。切号、注销、stopAndClear取消。独立sleepTimerFlow仅发模式/静态单调时钟截止时间，不向ClientUiState逐秒发射。
- **REQ-24 / AC-24 本地设置与个人资料接口**：keepScreenOnEnabled持久化、默认true；本批只补偏好/动作契约，既有页面接线留后续。clearImageCache清实际Coil内存/当前账号磁盘缓存，反馈CLEARING/CLEARED/FAILED/UNAVAILABLE，不报假成功。2026-11-14 新增：账号恢复/登录后读取 `user.avatar` 与 `/api/account/images/slots/avatar/avatar`，设置页支持修改当前账号昵称（`PATCH /api/account/profile`）、选择本地图片压缩为 `512×512` 静态 WebP 上传更换头像（`POST /api/account/images/upload/avatar` + `PUT /api/account/images/slots/avatar/avatar`）、移除头像，以及全屏查看头像大图并保存到相册。

## 数据与边界

客户端消费宿主已有接口，不自行调整实例配置、工作台/歌词资产或来源顺序。宿主歌词问题由主协作在另一个仓库处理，不能通过客户端放宽parser或误报无词掩盖。当前Android修改许可不授权UI协作者读写真实凭据，也不授权正式发布。

历史与队列只存安全元数据，禁止Cookie/CSRF/resultRef/媒体临时URL；持久化失败可见，generation/串行IO/清理失败隔离防止账号串用。仅debug启用结构性脱敏歌词诊断，release关闭；不写歌词正文、URL、ID或凭据。

离线下载、持久音频缓存、新推荐算法、歌词编辑、AI配置、插件私有业务、管理员管理、系统保活绕过、iOS和正式发布仍后置。歌单/收藏写入和普通账号收听统计的原后置决定已由本轮听歌能力补全明确替代。客户端POST译文生成仅由用户明确动作触发；统一GET仍按服务端工作台的既有自动补全策略返回ready/pending/not_needed等状态，客户端不推断语种或自行决定资格。译文显示偏好不触发POST，不是必要播放链路。远程WIP备份和本轮平板覆盖更新已由用户分别授权，不扩大为发布权限。
