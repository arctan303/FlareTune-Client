=====================================================================
0. 这份材料是什么 / 怎么来的
=====================================================================

对象：音流（Musiver），包名 cn.musiver.android，版本 2.0.1-beta.15。
     Kotlin + Jetpack Compose 原生客户端（2.0 是重写版，1.x 是 Flutter）。
来源：真机 adb pull 的已安装 base.apk，classes.dex / classes2.dex 共 12315 个类。

取证方式：直接读 smali 字节码。R8 混淆了类名与方法名，但
  字符串常量、Kotlin data class 的 toString 片段、枚举字面量、
  浮点常量、以及 Compose 库保留的方法名（spring / tween / animateFloatAsState）
  都完整保留，所以下面的结论都能落到具体指令或具体数值上。

标注约定：[DEX] = 字节码直读；[推断] = 由字节码结构推出、无直接常量佐证。
最后一节列没能确定的部分，不要把那节当已知。

本文只讲**换行时的动画**（换行那一刻什么在动、用什么曲线、动多少）。
滚动位置怎么解算、偏移怎么约束，另见
gemini-brief-musiver-lyrics-scroll.txt。

本主题涉及的 R8 类名映射：

  Lv44;  = 单行歌词组合函数
  Lx24;  = 动画场景枚举

=====================================================================
1. 先说结论
=====================================================================

换行不是一个动画，是三层同时发生：

  A. 行的位置与缩放 —— 两个欠阻尼 spring，会过冲再回弹（这就是"弹"）
  B. 行与行之间的呈现差异 —— 四档表，越远越淡、越小、越模糊
  C. 逐字的强调脉冲 —— 每个字独立形变，相位按字数错开

两个 spring 参数（都能在字节码里读到）：

    行的 y      spring(dampingRatio = 0.833333f, stiffness = 100f)
    行的 scale  spring(dampingRatio = 0.883883f, stiffness = 50f)

  dampingRatio < 1 是欠阻尼 —— 冲过目标再回来，回弹幅度不大但看得见。
  stiffness 100 / 50 都比 Compose 内置最低档 StiffnessLow = 200 更软，
  所以是"慢而弹"，不是那种很脆的快弹。


=====================================================================
2. 动画场景枚举：靠场景选规格
=====================================================================

  enum 动画场景 { None, Spring, LineAdvance, ContainerResize } [DEX]
  （字面量原样保留，顺序即 ordinal 0..3）

  R8 生成了一张 ordinal 重映射数组，长度 4，
  **只有 ContainerResize 那一格被标成 1**，其余全是 0。 [DEX]

  选规格的逻辑：

    if (场景 == ContainerResize) spec = tweenSpec
    else                        spec = spring

  也就是：转屏 / 字号变化这类"容器尺寸变了"的情况用固定时长曲线，
  其余（含换行 LineAdvance 和常规跟随）全部用 spring。

  两个 spring 规格是静态常量，构造时直接写死参数： [DEX]

    spring A = spring(dampingRatio = 0.833333f,  // 0x3F4F5C55
                      stiffness    = 100f,       // 0x42C80000
                      visibilityThreshold = null)
    spring B = spring(dampingRatio = 0.883883f,  // 0x3F63D9F0
                      stiffness    = 50f,        // 0x42480000
                      visibilityThreshold = null)

  分配关系：行的 y 用 spring A，行的 scale 用 spring B。 [DEX]
  位置比缩放更"硬"一点（阻尼更低、刚度更高），
  缩放更软更慢 —— 所以视觉上先看到整行滑过去，再看到它涨到该有的大小。


=====================================================================
3. ContainerResize 走 tween
=====================================================================

    tween(durationMillis = 300, delayMillis = 0,
          easing = CubicBezierEasing(0.4f, 0.0f, 0.2f, 1.0f)) [DEX]

  缓动常量是静态字段，四个控制点直接写在 <clinit> 里。

  为什么这条单独走曲线：转屏时位移可能是几百像素，
  弹簧在这种情况下会明显过冲，观感失控。固定 300ms 的
  ease-in-out 变体更可控。


=====================================================================
4. 逐行错峰：每行延迟不同
=====================================================================

求解器给每一行算一个 delay（单位秒），换行时各行按这个延迟先后启动。 [DEX]

    步长 step 初值 0.05 秒（50ms）
    每铺一行：delay += step
    过了锚点之后：step /= 1.05f

  所以延迟序列是 0 / 50 / 98 / 145 / ... 毫秒 —— 增量逐行衰减，
  远处行不会无限滞后。这个衰减是"波浪感"而不是"排队感"的关键。

  延迟最终 ×1000 转毫秒、取整、下限 0，交给每行的动画状态。

  细节：延迟只在行落到容器顶部以下（y >= 0）时才开始累加。 [DEX]

  错峰让整片文字不是齐刷刷一起动，而是靠锚点先到、远处后到。
  这是"丝滑"里最容易被误认为"缓动曲线好"的那一层，
  实际上是时间轴被拆开了。


=====================================================================
5. 行呈现四档表
=====================================================================

每一行算出一个 LyricsLinePresentation(opacity, scale, blurRadius,
verticalOffset, isHighlighted)。 [DEX]

先算"这一行到最近的高亮行之间的距离"（带符号），
取绝对值查表，符号决定垂直偏移的方向：

  |d| = 0（当前行）  opacity 1.00   scale 1.000   blur 0.0   offset 0
  |d| = 1           opacity 0.78   scale 0.985   blur 0.5   offset ∓2
  |d| = 2           opacity 0.56   scale 0.965   blur 1.2   offset ∓5
  |d| >= 3          opacity 0.34   scale 0.935   blur 2.2   offset ∓16
  没有高亮行时      opacity 0.72   scale 1.000   blur 0.0   offset 0

  （数值全部读自字节码常量：0.78 / 0.985 / 0.5 / 2.0；
    0.56 / 0.965 / 1.2 / 5.0；0.34 / 0.935 / 2.2 / 16.0；0.72）

  三件事同时发生：越远越淡、越远越小、**越远越模糊**。

  模糊是最关键也最容易漏的一层。它不是装饰，是在制造景深，
  让当前行从一堆同色文字里浮出来。blurRadius 从 0.5 递增到 2.2，
  和 opacity 一起下降，视觉上像"退到后面去了"而不是"变暗了"。

  verticalOffset 给远处行一个朝外的微小位移（2 / 5 / 16），
  配合缩放形成"被推开"的观感。符号来自距离的正负，
  也就是上方的行往上推、下方的行往下推。


=====================================================================
6. 逐字强调：把一行拆成字符做脉冲
=====================================================================

两层的量：

  LyricsEmphasizeAmplitude(scale, glow, durationMs)      —— 这一行的强度
  LyricsEmphasizeCharVisual(scale, offsetXEm, offsetYEm, glowOpacity)
                                                          —— 某个字此刻的形变

单字视觉的算式（常量全部读自字节码）： [DEX]

    n   = max(1, 这一行的字数)
    idx = 这个字在行内的序号（0 起）
    per = durationMs / 2.5 / n * idx        // 每个字的相位错开量
    p   = (当前播放位置ms - 行起始ms - per) / durationMs

    // 包络：只在 0 < p < 1 的区间内起作用
    // 两段三次缓动，中点取 1、两端取 2
    e = 1 - (1 - 2p)^3      (p >= 0.5)
    e = 1 - (2p - 1)^3      (p <  0.5)

    scale       = 1 + 0.1   * e * amp.scale
    offsetXEm   = -0.03 * e * amp.scale * (n / 2 - idx)      // 单位 em
    offsetYEm   = -0.025 * e * amp.scale - 0.05 * sin(2π * p) // 单位 em
    glowOpacity = e * amp.glow

  四个可读的设计：

  · offsetX 与 (n/2 - idx) 成正比 —— 越靠两边的字横向位移越大，
    整行看起来是"从中间向外张开"。 [DEX]

  · offsetY 里有一项 0.05 * sin(2π p)：每个字在脉冲期间做一次完整正弦摆动。
    这是"抖一下"的来源，也是"弹"在字级别的体现。 [DEX]

  · 相位错开量 per 按字数平摊（durationMs / 2.5 / n），
    字越多逐字错峰越细，整行看起来像一条波浪扫过。 [DEX]

  · 所有位移都用 em 为单位（不是 px），字号变化时形变比例不变。

  幅度随播放位置增长（自变量是"这一行已播放的毫秒数"）： [DEX]

    t     = max(1000, 位置ms)
    k1    = (t / 2000) 先三次方；t > 2000 之后改用开方
    k2    = (t / 3000) 同样处理
    scaleAmp   = min(1.2, k1 * 0.6)
    glowAmp    = min(0.8, k2 * 0.5)
    durationMs = t * 1.2
    （另有一个布尔开关会把 scale 再乘 1.6、glow 乘 1.5，
      之后仍被 1.2 / 0.8 截断）

  也就是说换行瞬间幅度小、约两秒内涨到上限，之后保持。
  这条设计避免了"每句都弹一样大"的机械感。

7. 歌词的另外两条动画（与换行不共用）
=====================================================================

  · LyricsKaraokeMaskStops(solidEnd = ...)   逐字填充的遮罩边界
  · LyricsInterludeDotsFrame(scale = ...)    间奏"..."的缩放帧
  · LyricsWordFill(lineIndex = ...) / LyricWordModel(text = ...)  词级模型
  · LyricsInterludePresentation(previousLineIndex = ...)

这几种和换行那三层是分开的数据结构，各有自己的驱动，
不共用第 2 节那两个 spring。 [DEX]


=====================================================================
8. 一条完整的时间线（换行那一刻）
=====================================================================

  T+0ms     当前行 index 变化 → 场景置为 LineAdvance
            重新解算所有行的 Target（y / scale / delay）
            行级动画状态开始朝新目标 spring
            锚点行 delay = 0，立刻动
            往下第 1 行 delay = 50ms，第 2 行 98ms，逐行递减增量

  T+0ms     行呈现四档表按新距离重算：
            新行 opacity 1.0 / scale 1.0 / blur 0，
            旧行降到 0.78 / 0.985 / blur 0.5

  T+0ms     逐字强调开始：字 0 立即起，字 i 晚 durationMs/2.5/n*i
            每个字在脉冲期内做一次 0.05em 的垂直正弦摆动，
            同时从行中心向外张开 0.03em * (n/2 - idx)

  T+~600ms  弹簧收敛（dampingRatio 0.83 / stiffness 100，欠阻尼过冲一次）

  容器尺寸变化（转屏）时走另一条路：
  tween 300ms + cubic-bezier(0.4, 0, 0.2, 1)，不弹。


=====================================================================
9. 为什么看起来"丝滑"
=====================================================================

  1. 欠阻尼（0.833）带来一次轻微过冲，而不是生硬的 ease-out 停住。
     过冲幅度小、周期短，观感是"有重量"而不是"抖"。

  2. 位置（stiffness 100）比缩放（50）快，两者不同步 ——
     整行先滑到位，再涨到该有的大小，多了一个时间差。

  3. 逐行延迟（50ms 起、递减增量）让追随有方向感：
     靠锚点先到，远处后到，形成波浪而不是排队。

  4. 远处行同时变淡、变小、变模糊（blur 0.5 → 2.2），
     把深度做出来了，运动感被放大。

  5. 字级脉冲带正弦摆动和逐字相位差，让"换行"这个事件
     在字的时间尺度上也有内容，不只是行在动。

10. 没能确定的部分
=====================================================================

  · 逐字包络那两段三次缓动在字节码里是交叉分支，
    "中点 1、两端 2"这个形状是按常量与跳转目标推的，
    没在真机上逐帧核对过实际曲线。
  · 行级动画状态的第一个 float 参数到底是目标值还是起始值，
    没能对齐到寄存器（函数形状是 animateFloatAsState 那种：
    两个 float + 一个 Int 延迟 + 一个 Long 时间 + AnimationSpec）。
  · blur 的 0.5 / 1.2 / 2.2 单位是 dp 还是 px 未确认。
  · 第 6 节那个"把 scale 再乘 1.6、glow 乘 1.5"的布尔开关
    到底代表什么（是否高亮行？是否关闭动效？）没还原出来。
  · 第 7 节四条动画的具体参数没展开，只确认了数据结构存在。
  · 上述数值都来自 Android 2.0.1-beta.15，iOS / 桌面端是否一致未验证。

想补这些，唯一可靠的办法是真机录屏逐帧量：
把一次换行拆成 60fps 序列，量每行的 y 曲线（能看到过冲幅度和周期），
量 opacity 与 blur 的到达时间（能反推 spec 与 delay）。
