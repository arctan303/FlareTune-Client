# 05 · 横向对比

## 2. 三家真正达成共识的 7 件事

这三家在审美上分歧很大，但以下做法完全一致 —— 说明这是品类约束，不是风格选择：

1. **封面是唯一色源**。界面本身不提供装饰色，颜色全部来自内容。
2. **播放页必须有沉浸背景**（模糊图 / 封面主色 / 对角渐变），且一定配遮罩。
3. **进度条极细**：1.5–4dp，配小圆点 thumb。
4. **筛选用胶囊 chip**，高度 32–48，圆角 = 高度一半。
5. **卡片圆角集中在 8–16dp**，没有一家用大圆角（>20）做内容卡。
6. **mini player 与主导航解耦**（悬浮或贴底），并且都带封面 + 标题 + 艺人 + 播放键。
7. **数字必须处理**（等宽或专用字形），因为时长/进度会高频变化。

## 3. 三家的关键分歧（决定"像谁"的地方）

| 分歧点 | 深色密度派（Spotify） | 浅色秩序派（Apple） | 氛围派（音流） |
| --- | --- | --- | --- |
| 界面"重量" | 重（信息多、字号小、间距紧） | 轻（信息少、字号大、留白多） | 中（一屏只放一件事） |
| 视觉记忆点 | 品牌绿 + display 标题 | 排版秩序 + 88dp 播放条 | 黑胶 + 全屏照片 |
| 对内容量的假设 | 内容无限多 | 内容精选过 | 内容在用户自己的服务器上 |
| 适合谁抄 | 平台型产品 | 内容策展型产品 | **个人自建库** |

**对 FlareTune 的意义**：FlareTune 是"自己的服务器 + 自己的库"，内容量中等、
策展需求低、氛围需求高。所以**最接近的参照是音流，最该学的方法是 Spotify 的 token 纪律，
最该学的单屏是 Apple 的播放器与歌词**。

## 4. 抄什么 / 不抄什么（结论表）

| 抄 | 来源 | 具体形态 |
| --- | --- | --- |
| 四套 token 阶梯 | Spotify | 间距 / 字号 / 圆角 / 控件尺寸，比例照搬，数值按中文微调 |
| 中性灰 + 单一强调色 | Spotify | 强调色只给"正在播放/已加入/主按钮" |
| chip 48 高 / 24 圆角 | Spotify | 筛选条、标签页 |
| 数字等宽 | Spotify + Apple | 时长、进度、曲目序号 |
| 歌词块间距 > 行高 | Apple | 中文：正文 20–22sp、行高 1.35、块间距 28–32 |
| 88dp 浮动 mini player | Apple | 但可缩到 72–80dp 以适配小屏 |
| 渐变卡替代缺失封面 | Apple | 双色渐变 + 白色粗体标题 |
| 黑胶唱片 | 音流 | 作为**可开关**的播放器形态 |
| 封面模糊背景 | 音流 | 必须配 0.5–0.6 遮罩与对比度下限 |
| 播放器三段 tab | 音流 | 播放 / 队列 / 歌词 一屏切换 |
| 裁切即提示 | Spotify + Apple | 横向列表露出 8–12% |

| 不抄 | 来源 | 原因 |
| --- | --- | --- |
| 5 套图标字体 | 音流 | 笔画不一致，是"不像产品"的主因 |
| 9sp 字号 | Spotify | 中文不可读 |
| 48sp 中文标题 | Spotify | 汉字折行难看，上限 40（英文）/ 30（中文） |
| 1.08 行高 | Apple | 汉字会挤 |
| iOS 手势搬 Android | Apple | 平台不认 |
| 无强调色 | 音流 + Apple | 缺少品牌识别锚点 |
| minSdk 30 | Apple | 除非确认放弃旧设备，否则 26–29 更稳 |

## 5. 一句话

> **结构抄 Spotify，秩序抄 Apple，氛围抄音流，但把音流的工程短板补齐。**
