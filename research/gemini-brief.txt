Apple Music 7.0.0 全屏播放页的实现细节

样本：com.apple.android.music 7.0.0（versionCode 1614），minSdk 30。
来源：反编译 res/layout、res/anim、resources.arsc，以及 dump 4 个 dex 的 dalvik 指令。
以下数值都是从 APK 里读出来的。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
一、页面层级
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RelativeLayout
└── ConstraintLayout (player_root)
    ├── LyricsBackgroundLayerView (background_layers)   流动背景，初始 alpha=0
    │     背景是 16dp 顶部圆角 + #FF424242 纯色打底
    ├── Guideline（歌词缩略图对齐基准，begin=32dp）
    ├── ViewSwitcher (motion_switcher)                  动态封面图层，初始 alpha=0
    │     inAnimation = android:anim/fade_in
    │     outAnimation = android:anim/fade_out
    │     ├── motion_container1
    │     └── motion_container2
    ├── FrameLayout (player_fragments_host)             歌词页 / 队列页
    │     └── View (nav_bar_divider)  #14FFFFFF
    └── mini_player                                     同一份 mini player 复用

两个 motion_container 交替使用：切歌时先在第二个容器里准备好新封面，再整体交叉淡入，
所以封面不会直接跳变，也不需要自己写 crossfade 动画。

motion 容器内部（view_motion_container.xml）：

  ConstraintLayout
  ├── TextureView (motion_texture)
  │     0dp × 0dp，constraintDimensionRatio = "H,3:4"，贴顶，左右撑满
  ├── PlayerTransitionImageView (motion_preview_frame)   完全覆盖 texture
  ├── Barrier (motion_barrier)
  │     barrierDirection = bottom，barrierMargin = -22dp，ref = motion_texture
  ├── View (motion_legibility_gradient)                  全屏可读性渐变
  ├── View (motion_blur)                                 scaleY = -1，top 约束到 barrier
  └── View (motion_color_gradient_overlay)               top 约束到 texture 底部

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
二、背景：每帧实时合成，不是一张模糊图
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

自定义 View（LyricsBackgroundLayerView）收到封面后，在 onDraw 里按当前时间实时合成背景 bitmap。

生成流程（b(Bitmap, w, h, timeMs, Context) 反编译还原）：

1. 目标尺寸 = 视图尺寸 × 1.3
2. createBitmap(w×1.3, h×1.3, ARGB_8888)
3. 三层 drawBitmap，每层：
     Matrix.setScale(k, k)，k = 1.3 × 目标尺寸 / 原图尺寸
     Matrix.postRotate(animValue, cx, cy)
     Matrix.postTranslate(dx, dy)
     Paint 挂 ColorMatrixColorFilter(ColorMatrix().setSaturation(2.5f))
4. 用封面取到的两个颜色 drawPaint 打底
5. RenderScript 高斯模糊，radius = 25
6. createBitmap + drawBitmap 缩放输出

三个旋转动画（ValueAnimator）：
  时长 120000ms / 90000ms / 70000ms
  都是 LinearInterpolator + setRepeatCount(-1)
  每帧 setCurrentPlayTime(System.currentTimeMillis())

背景用真实时间驱动，跟播放进度无关。所以暂停时背景还在缓慢流动，切歌也不重新计时。
三个周期互不整除，叠加后视觉效果是"永远不重复的缓慢流动"。

常量还原：
  1067869798 = 1.3f      放大倍数
  1075838976 = 2.5f      饱和度
  -1082969293 = -1.0f    第2层 X 偏移系数
  -1087163597 = -0.8f    第2层 Y 偏移系数
  -1090519040 = -2.0f    第3层平移基数
  1060320051 = 0.7f      第3层 Y 系数

缓存：HashMap<Pair<w,h>, Pair<Bitmap, Canvas>>，按视图宽高做 key，尺寸不变就不重算。
onSizeChanged 和 onDraw 都走这个缓存。
有 setReducedEffects(boolean) 可以整套关掉（系统"减少动画"或低电量模式）。

镜像模糊层（封面只占屏幕上方 3:4）：
封面用 TextureView 按 H,3:4 铺在上方，下半屏用"封面底边的翻转副本 + 模糊"填满。
具体做法是一个 View 设 scaleY=-1，top 约束到 barrier，barrier 的 margin 是 -22dp
（往封面里多压 22dp，保证接缝处不露白边）。
这样整屏都是同一张图的气质，但没有生硬的分界线，也不需要额外素材。

遮罩层：
  全屏可读性渐变，基色 #B3171717（70% 黑）
  封面下方再叠 #59000000（35% 黑）
  歌词列表背后 #4D000000（30% 黑）
  没拿到封面时兜底 #FF424242 + 顶部圆角 16dp

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
三、动效
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

进场 250ms，退场 300ms，都是 decelerate_interpolator，整屏 translateY 100%p：

  activity_slide_up.xml     duration = @integer/slide_animation_duration = 250
                            fromYDelta 100%p → 0
  activity_slide_down.xml   duration = 300（硬编码，没走资源）
                            fromYDelta 0 → 100%p
  activity_fade_in.xml      duration 200ms，accelerate_decelerate
  activity_hold.xml         duration 250ms，translate 不动，zAdjustment=-1

出比进慢 50ms。activity_hold 的存在说明这是双 Activity 叠层：上层滑入时下层不动，
只被 zAdjustment=-1 压到后面。所以播放页是"盖上来"，不是"把页面推走"。

通用滑动（BottomSheet / Fragment）用 config_shortAnimTime = 200ms，无自定义插值器。

播放页本身是 BottomSheet：
  PlayerBottomSheetBehavior extends Material 的 BottomSheetBehavior
  只覆写了 4 个方法：getExpandedOffset / onNestedPreScroll / onNestedScroll / 拖拽判定
  player.xml 里 app:behavior_peekHeight = 0dp（收起时完全不可见，没有半露的播放条）
  onBottomSheetSlide(float) 里，slide <= 0.3f 时切换系统栏明暗

另有一个 rotation_anim.xml：objectAnimator rotation 0→360，500ms，repeat=-1。
500ms 一圈太快，这不是黑胶唱片，是加载 / 缓冲指示器的旋转。

四、歌词
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

布局：

  ConstraintLayout（marginTop 32dp，黑底）
  ├── 顶部当前曲目条
  │     MaterialCardView 圆角 5dp，描边 0.5dp #1A000000
  │       ├── TextureView 60×60（动态封面）
  │       └── PlayerTransitionImageView
  │     标题（BodyEmphasized，marquee 只跑 1 次）
  │     副标题（Body，alpha 45%）
  │     喜欢 / 更多
  ├── AlphaGradientFrameLayout（recycler_view_gradients）  上下边缘渐隐
  │     └── RecyclerView（lyrics_main_content）
  ├── Guideline（tap_target_guideline，42.5%）
  ├── FrameLayout（controls）高度 = 屏高 34.5%
  ├── translations_button
  ├── VocalAttenuationControl（人声衰减旋钮）
  └── loading_progress

控件区固定占屏高 34.5%，点击区从 42.5% 开始，中间 8% 是"点了不跳转也不误触"的缓冲带。

字号与间距：
  lyrics_line_text_size              34sp（Title0Emphasized）
  lyrics_line_secondary_text_size    22sp（Title2ShortEmphasized）
  lyrics_line_static_line_height     26sp（Body，静态歌词）
  lyrics_line_between_line_spacing   32dp
  lyrics_static_between_line_spacing 40dp
  lyrics_static_top_margin           30dp
  lyrics_text_padding_top            2dp
  lyrics_text_padding_bottom         10dp
  lyrics_text_padding_horiz          12dp
  lyrics_line_margin_horiz           20dp
  lyrics_line_padding_horiz（静态）  32dp

行内左右 padding 12 + 行 margin 20，合计左右留白 32dp。
34sp 在 1080p 屏上一屏只放 4~5 行，它是把歌词当海报排版，不是当文本。

行状态：
  非当前行 scale 0.98，当前行 scale 1.0
  当前行 #F0FFFFFF（94% 白），非当前行 #73FFFFFF（45% 白）
  只有 2% 的缩放差异，配合颜色层级就够了，不用 0.8 / 1.2 那种夸张缩放

逐字高亮（卡拉OK）：
  每个字是一个独立的 CustomTextView（lyrics_word_karaoke.xml），用 Flexbox 排成一行
  逐字上色就是改那个字的 textColor，不需要复杂的 span

  整行边缘羽化由 FullWidthAlphaGradientFlexboxLayout 做，dispatchDraw 逻辑：
    for (SparseArray<Mask> masks : new SparseArray[]{mMasks, mBgMasks}) {
        for (Mask m : masks) {
            if (m.dirty) {
                m.rect.set(0, top + m.topInset, width, height - bottomInset);
                m.paint.setShader(new LinearGradient(
                    0, m.rect.top, width, m.rect.bottom,
                    m.colors, m.positions, Shader.TileMode.CLAMP));
                m.dirty = false;
            }
        }
    }
    int save = canvas.saveLayer(0, 0, w, h, mLayerPaint);
    super.dispatchDraw(canvas);
    // 逐 mask drawRect 做 alpha 遮罩
    canvas.restoreToCount(save);

  关键是用"一个共享的渐变遮罩"而不是给每个 TextView 单独设 alpha。
  这样一行里所有字共享同一个渐变坐标系，边缘过渡是连续的。

  逐字参数：
    lyrics_karaoke_gradient_feather_width        30dp    高亮边缘羽化宽度
    lyrics_karaoke_syllable_lift                 -2dp    唱到的音节上浮
    lyrics_karaoke_emphasis_shadow_radius        5dp     强调字阴影
    lyrics_karaoke_badge_shadow_radius           3dp     徽章阴影
    lyrics_karaoke_badge_shadow_alpha            0.6
    lyrics_karaoke_duet_line_width_percent       0.85    对唱行宽度占比
    lyrics_instrumental_dot_size                 10dp    间奏圆点直径
    lyrics_instrumental_dot_margin_horiz         6dp

  羽化 30dp 在 34sp 的字上，意味着高亮是"扫"过去而不是"切"过去。
  音节上浮 2dp 几乎看不出来，但去掉之后整个效果会变平。

滚动策略：
  ItemAnimator 的 animateChange 直接 return true，不做任何 item 动画。
  因为歌词是整体滚动的，每行再各自动会打架，所以行内容更新是瞬时的，动感全靠滚动本身。

  用户手动滚动后 7000ms 内不自动跟随，之后恢复自动居中。

边缘渐隐容器：
  AlphaGradientFrameLayout 包住 RecyclerView，gradient_edge = 0x0F（低 4 位 flag：
  1=左 2=上 4=右 8=下，四边全开）。
  getBottomFadePositions() 返回 float[]，可以运行时调整。
  进入 / 退出歌词页时，边缘渐变位置和控件透明度是一起动画的，
  所以控件是"沉下去"而不是"消失"。

六、颜色
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

播放页所有文字和图标只用白色四档 alpha，不调色相、不加灰：

  player_vibrant_primary      #F0FFFFFF（94%）  歌词当前行、曲名
  player_vibrant_secondary    #73FFFFFF（45%）  艺人名、副标题、进度条已播放
  player_vibrant_tertiary     #2EFFFFFF（18%）  未播放轨道、次要图标
  player_vibrant_quarternary  #14FFFFFF（8%）   分隔线、极弱元素

理由是背景是流动的彩色，任何固定灰都会显脏。

七、未能还原的部分
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 逐字高亮的时间轴推进
   com.apple.android.music.ttml.javanative.LyricsController 是 JNI 包装，
   TTML 解析和逐字时间对齐都在 native 层。只能确认按 syllable 粒度驱动，看不到具体算法。

2. 歌词行滚动的插值曲线
   RecyclerView 的 smoothScroll 没有显式 duration，走 LinearSmoothScroller 默认速度
   （按像素/毫秒算），没反编译到具体系数。

3. BottomSheet 的 peek / expanded 偏移
   PlayerBottomSheetBehavior 里没有常量，由父类按 peekHeight 计算，
   而 peekHeight 在代码里设，只在 player.xml 里看到是 0。

4. lyrics_line_scale_highlight 的确切值
   ARSC 里被解析成 4161536.0px，按 <<8 还原是 1.0f，但同组的 _normal 是未经此变形的 0.98，
   两者编码方式不一致。推测是 ≈1.0，未在真机核实。

5. 三层 drawBitmap 的确切目的
   如果 Paint 没有设 xfermode，三层就是纯 SRC_OVER 叠加，后画的会完全覆盖先画的，
   前两层等于白画。推测是旋转后 1.3 倍的图在角落会露出空白，三层不同角度正好互补，
   但没有验证。

补充：数值都取自 APK 的默认 values 目录（手机竖屏）。
Apple 还有 values-sw600dp、values-xxhdpi 等多套限定符覆盖，宽屏和不同 dpi 下的值不同。
